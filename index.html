What this looks like in practice

Six things you might need, and what I would actually do

Every scenario below links to working code that proves the claim — infrastructure-as-code, tests, and a written account of what the build got wrong before it got it right. Ask the assistant at the bottom of this section if you want to dig into any of them.

Proven

“We need to migrate this database, and we need to be able to go back.”

A pre-flight assessment that blocks the migration if the schema will not survive it, then parity proven by content checksum rather than row count — because two tables with the same number of rows can still differ. The rollback is restored and verified in a drill, not documented and hoped for.

Proven

“Our DR plan says four hours. Is that true?”

Almost certainly not, because the clock usually starts when somebody runs the failover command — which excludes detection and decision, the part of an outage that is actually longest. I fail the estate over for real and time it from the first failed write, then count data loss by comparing what the old primary acknowledged against what survived.

Azure SQLFailover groupsRTO/RPORunbooks
Proven

“We are about to turn on Conditional Access and we are nervous.”

Rightly so — it is the one control that can lock you out of the thing you would use to undo it. Policies deploy report-only and get evaluated against a declared matrix of sign-ins before anything is enforced, including a check that the break-glass accounts can still reach a recovery surface. Promotion is something the evaluation has to earn.

Entra IDConditional AccessGraph APITerraform
Proven

“We acquired a company and now we have two directories.”

The work that decides whether the cutover goes well happens weeks earlier, in the objects: namespaces that cannot be verified, two people holding the same address in different letter case, a disabled leaver holding the sign-in name a new starter needs. I assess that against the live directory, and I check the filter change that silently deletes accounts in the cloud rather than disabling them.

Proven

“Show us that our access model is actually least privilege.”

Not by reading role assignments — by signing in as each identity and attempting what it is supposed to be refused. The analysis is written to avoid the false positives that make these reports unreadable: an account excluded from a policy by group membership is not a finding, and neither is the break-glass account that is meant to hold standing privilege.

Proven

“Our integration loses messages and we cannot reproduce it.”

Then it needs to be tested against the failures that actually happen: the same message delivered twice, a poison message that must not block the queue behind it, two consumers racing for the same work, and a replay path that repairs what it understands and refuses what it does not. At-least-once delivery is a contract, and most code assumes exactly-once.
